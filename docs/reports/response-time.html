What this suggests

Not yet measured; each is to be tested against this baseline with accuracy held.

  1. Return the answer before verification. The answer and its checked citations are ready after generation; the per-sentence support marks could follow. Takes the whole verification stage out of the wait (p50 3.3 s, p90 10.2 s) without changing any answer.
  2. Fewer rerank candidates. Scoring 12 to 15 passages instead of 30 could roughly halve the 2.9 s stage, if retrieval recall holds. make eval-retrieval measures that without the chat model.
  3. Cheaper verification. Matching sentences to passages by embeddings would take milliseconds instead of seconds, but it decides which statements show as unsupported, so it needs its own accuracy check.
  4. Keep models loaded. A longer keep-alive removes the cold start (6.2 s of reranker loading) at the cost of holding about 7.7 GB of models in memory.
  5. Shorter answers or a smaller evidence budget. Fewer tokens are the most direct lever, at about 27 ms per output token, but the riskiest for accuracy.

How it was measured

Setup

Machine

Ollama
0.35.1, every model local
Answer model
qwen3.5:9b, thinking off
Embeddings
embeddinggemma, 768 dimensions
Reranker
Qwen3-Reranker-0.6B (F16), 30 candidates, 4 at a time
Settings
defaults: verification on, second hop always, contextual chunk summaries, structure chunker, 9,000-character evidence budget, small-talk margin 0.11
Code
commit 9896220 plus the stage-timing changes

Questions and method

Corpus
the four fixture sets (company, testing, Northstar, Indian-language), indexed in a scratch schema in 133 s
Questions
fixtures/latency-questions.json: 30 from questions.json (single, cross-document, unknown, conflicting, follow-ups with parents), 3 list, 4 multi-hop, 8 Indian-language, 4 small talk
Mode
one question at a time, in process (no HTTP), not streamed
Stage times
the pipeline's own stage markers (metrics.stages_ms): each stage from its start to the next one's

Limitations

  • One run on one machine, one question at a time. Concurrent users share a single model slot and wait for each other; this run does not show that.
  • Not streamed. In the app the answer appears as a draft while it is generated, so text shows up sooner than these totals (streamed answers record this as metrics.first_draft_ms).
  • Few questions per type. Per-type figures are indicative.
  • Accuracy in this run: 41 of 45 document questions correct. The harness has no small-talk category, so its score counts the four small-talk messages as wrong; all four got a reply in about a second.
